# راهنمای قدم‌به‌قدم راه‌اندازی Digi Cyber

این راهنما از صفر تا انتشار اپ روی گیت‌هاب خودتان را مرحله به مرحله توضیح می‌دهد. وقتی تمام شد:

- یک مخزن (Repository) گیت‌هاب مال خودتان دارید که صفحه‌ی اولش، صفحه‌ی دانلود اپ برای مشتری‌هاست.
- فایل‌های نصب ویندوز، مک، لینوکس و اندروید خودکار ساخته، تست و منتشر می‌شوند.
- برای انتشار نسخه‌ی جدید فقط یک عدد را عوض می‌کنید و تغییرات را به گیت‌هاب می‌فرستید.

اپ به هیچ سرور یا اکانت دیگری وابسته نیست. آدرس هیچ سروری داخل اپ نیست و همه چیز از لینک اشتراک خود مشتری می‌آید.

**زمان لازم:** حدود یک ساعت، که بیشترش منتظر ماندن برای ساخت خودکار است.

**قرارداد این راهنما:** هر جا `USERNAME` آمده، نام کاربری گیت‌هاب خودتان را بگذارید. اگر برای مخزن نامی غیر از `digi-cyber` انتخاب کردید، هر جا `digi-cyber` در آدرس‌ها آمده همان نام را بگذارید. دستورهای داخل کادرهای خاکستری را عیناً در ترمینال بزنید؛ هر خط یک دستور است و بعد از هر خط Enter بزنید.

## گام ۰: نصب ابزارها (یک بار)

سه چیز لازم دارید: اکانت گیت‌هاب، برنامه‌ی **Git**، و **جاوا (JDK)** که فقط برای ساخت کلید اندروید در گام ۵ لازم است.

### اکانت گیت‌هاب

اگر ندارید، در سایت github.com روی **Sign up** بزنید و اکانت بسازید. نام کاربری شما در آدرس صفحه‌ی دانلود دیده می‌شود، مثلاً `github.com/USERNAME/digi-cyber`.

### ویندوز

۱. برای نصب **Git** به آدرس https://git-scm.com/download/win بروید و بالای صفحه روی لینک **Click here to download** بزنید. فایل دانلودشده را اجرا کنید، در همه‌ی صفحه‌ها **Next** و در آخر **Install** را بزنید. همراه آن برنامه‌ی **Git Bash** هم نصب می‌شود؛ همه‌ی دستورهای این راهنما را در Git Bash می‌زنید.

۲. برای نصب **جاوا** به آدرس https://adoptium.net بروید و دکمه‌ی دانلود آخرین نسخه‌ی **Temurin** را بزنید. فایل دانلودشده (با پسوند msi) را اجرا کنید و با همان گزینه‌های پیش‌فرض نصب کنید.

### مک

۱. برای نصب **Git** برنامه‌ی **Terminal** را باز کنید: کلیدهای Command و Space را با هم بزنید، بنویسید Terminal و Enter بزنید. در آن دستور `git --version` را بزنید. اگر Git نصب نباشد، مک پیشنهاد نصب **Command Line Tools** را می‌دهد: **Install** را بزنید و صبر کنید تا تمام شود.

۲. برای نصب **جاوا** از https://adoptium.net فایل آخرین نسخه‌ی **Temurin** (با پسوند pkg) را دانلود و نصب کنید.

### لینوکس (اوبونتو و دبیان)

این دستور را در ترمینال بزنید:

</div>

```bash
sudo apt install git default-jdk-headless
```

## گام ۱: باز کردن فایل زیپ

فایل زیپ را در یک جای ساده، مثلاً روی Desktop، باز کنید:

- **ویندوز:** روی فایل کلیک راست کنید، **Extract All…** و بعد **Extract** را بزنید.
- **مک:** روی فایل دوبار کلیک کنید.

داخل آن دو چیز هست: همین راهنما (فایل `START-HERE.md`) و پوشه‌ی **`digi-cyber`** که سورس کامل اپ است. از این به بعد همه‌ی کارها داخل پوشه‌ی `digi-cyber` انجام می‌شود.

## گام ۲: ساخت مخزن در گیت‌هاب

۱. وارد github.com شوید.

۲. بالا سمت راست روی علامت **+** بزنید و **New repository** را انتخاب کنید.

۳. در کادر **Repository name** یک نام بنویسید، مثلاً `digi-cyber`.

۴. گزینه‌ی **Public** را انتخاب کنید. این ضروری است: مشتری‌ها فایل‌ها را از بخش **Releases** همین مخزن دانلود می‌کنند و فایل‌های مخزن Private برای دیگران قابل دانلود نیست. ساخت خودکار هم برای مخزن Public رایگان و بدون محدودیت است.

۵. چیز دیگری اضافه نکنید: گزینه‌های **README** و **gitignore** و **license** روی Off یا None بمانند تا مخزن کاملاً خالی ساخته شود.

۶. دکمه‌ی **Create repository** را بزنید.

صفحه‌ای باز می‌شود که آدرس مخزن را به این شکل نشان می‌دهد. این آدرس را در گام بعد لازم دارید:

</div>

```
https://github.com/USERNAME/digi-cyber.git
```

## گام ۳: فرستادن سورس به گیت‌هاب

### ۳-الف) باز کردن ترمینال داخل پوشه‌ی digi-cyber

- **ویندوز:** پوشه‌ی `digi-cyber` را باز کنید، روی جای خالی داخل پوشه کلیک راست کنید و **Open Git Bash here** را بزنید. در ویندوز ۱۱ اول **Show more options** را بزنید.
- **مک:** در Terminal بنویسید `cd` و یک فاصله بگذارید، بعد پوشه‌ی `digi-cyber` را با ماوس داخل پنجره‌ی Terminal بکشید و Enter بزنید.
- **لینوکس:** داخل پوشه کلیک راست کنید و **Open in Terminal** را بزنید.

برای اطمینان دستور `ls` را بزنید. باید `package.json` و `android` و `src` و `README.md` را در فهرست ببینید.

برای چسباندن متن در Git Bash کلیک راست کنید و **Paste** را بزنید، یا کلیدهای Shift و Insert را با هم بزنید.

### ۳-ب) معرفی خودتان به Git (فقط بار اول)

این نام و ایمیل روی هر تغییری که ثبت می‌کنید می‌نشیند و در گیت‌هاب برای همه دیده می‌شود. در دو دستور زیر، به جای `Your Name` و `you@example.com` نام و ایمیل خودتان را بگذارید:

</div>

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

<div dir="rtl">

اگر نمی‌خواهید ایمیل واقعی‌تان دیده شود: در گیت‌هاب روی عکس پروفایل (بالا سمت راست) بزنید و **Settings** را باز کنید. در منوی سمت چپ **Emails** را بزنید و تیک **Keep my email addresses private** را بزنید. همانجا یک آدرس ایمیل ساختگی نشان داده می‌شود که به `users.noreply.github.com` ختم می‌شود؛ همان را به جای ایمیل در دستور بالا بگذارید.

### ۳-ج) ثبت و ارسال سورس

این دستورها را یکی‌یکی بزنید. در خط یکی مانده به آخر، آدرس را با آدرس مخزن خودتان از گام ۲ عوض کنید:

</div>

```bash
git init
git add -A
git commit -m "Digi Cyber 1.0.0"
git branch -M main
git remote add origin https://github.com/USERNAME/digi-cyber.git
git push -u origin main
```

<div dir="rtl">

### ۳-د) ورود به گیت‌هاب هنگام push

دستور آخر (`git push`) بار اول از شما می‌خواهد وارد گیت‌هاب شوید.

**در ویندوز:** پنجره‌ی **Connect to GitHub** باز می‌شود. **Sign in with your browser** را بزنید و در صفحه‌ای که در مرورگر باز می‌شود، دکمه‌ی **Authorize** را بزنید. این کار فقط بار اول لازم است.

**در مک و لینوکس:** Git نام کاربری (Username) و رمز (Password) می‌خواهد. **رمز اکانت گیت‌هاب اینجا قبول نمی‌شود**؛ به جای آن یک توکن بسازید:

۱. در گیت‌هاب روی عکس پروفایل بزنید و **Settings** را باز کنید.

۲. پایین منوی سمت چپ روی **Developer settings** بزنید. بعد **Personal access tokens** را باز کنید و **Tokens (classic)** را انتخاب کنید.

۳. دکمه‌ی **Generate new token** را بزنید و از منوی آن **Generate new token (classic)** را انتخاب کنید.

۴. در کادر **Note** بنویسید `push`، در **Expiration** یک مدت انتخاب کنید (مثلاً سه ماه)، و تیک دو گزینه‌ی **repo** و **workflow** را بزنید. تیک **workflow** حتماً لازم است، وگرنه گیت‌هاب فایل‌های ساخت خودکار را قبول نمی‌کند.

۵. پایین صفحه **Generate token** را بزنید و توکن را کپی کنید (با حروف `ghp` شروع می‌شود). این توکن فقط همین یک بار نشان داده می‌شود.

۶. وقتی Git پرسید، جلوی Username نام کاربری گیت‌هاب و جلوی Password همین توکن را بچسبانید. موقع چسباندن رمز چیزی روی صفحه دیده نمی‌شود؛ عادی است، Enter بزنید.

بعد از تمام شدن push، صفحه‌ی مخزن را در مرورگر رفرش کنید. فایل‌ها و صفحه‌ی دانلود (README) را می‌بینید.

## گام ۴: اولین ساخت و انتشار (خودکار)

همین push ساخت خودکار را شروع کرده است و لازم نیست کاری بکنید:

۱. در صفحه‌ی مخزن تب **Actions** را بزنید. یک اجرا با نام **Digi Cyber 1.0.0** (از نوع **Build**) با دایره‌ی زرد می‌بینید، یعنی در حال اجراست.

۲. صبر کنید. بار اول حدود ۳۰ تا ۵۰ دقیقه طول می‌کشد و دفعه‌های بعد حدود ۱۵ تا ۳۰ دقیقه. لازم نیست صفحه یا کامپیوتر روشن بماند؛ ساخت روی سرورهای گیت‌هاب انجام می‌شود.

۳. وقتی تیک سبز آمد، به صفحه‌ی اصلی مخزن (تب **Code**) برگردید. در ستون سمت راست، زیر **Releases**، نسخه‌ی **v1.0.0** آمده است با فایل‌های ویندوز، مک، لینوکس و فایل `SHA256SUMS.txt`.

از این لحظه لینک‌های دانلود صفحه‌ی اول مخزن کار می‌کنند، به جز لینک‌های اندروید که بعد از گام ۵ کار می‌کنند. در خلاصه‌ی این اجرا یک هشدار زرد با متن `No Android signing key` هم می‌بینید؛ عادی است و در گام ۵ برطرف می‌شود.

اگر به جای تیک سبز، علامت قرمز آمد، گام ۹ را ببینید.

## گام ۵: کلید امضای اندروید (یک بار، ضروری)

اندروید یک آپدیت را فقط وقتی روی نسخه‌ی نصب‌شده نصب می‌کند که هر دو با **یک کلید** امضا شده باشند. این کلید را یک بار می‌سازید و برای همیشه نگه می‌دارید. تا این کلید را به گیت‌هاب ندهید، نسخه‌ها بدون فایل APK منتشر می‌شوند.

### ۵-الف) ساخت کلید

در همان ترمینال گام ۳ (داخل پوشه‌ی `digi-cyber`) این دستور را بزنید:

</div>

```bash
bash scripts/make-android-key.sh
```

<div dir="rtl">

در آخر پیامی می‌بینید که با `Done` شروع می‌شود.

اگر پیام `keytool not found` آمد، جاوا (گام ۰) نصب نیست یا ترمینال قبل از نصب جاوا باز شده است: ترمینال را ببندید، دوباره باز کنید (گام ۳-الف) و دستور را تکرار کنید.

حالا پوشه‌ی تازه‌ی `android-signing` این سه فایل را دارد:

| فایل | چیست |
| --- | --- |
| `release.jks` | خود کلید |
| `secrets.txt` | رمز کلید و چهار مقداری که باید در گیت‌هاب بگذارید |
| `ANDROID_KEYSTORE_BASE64.txt` | کل کلید به شکل متن، برای گذاشتن در گیت‌هاب |

این پوشه خودکار از Git بیرون گذاشته می‌شود و با push به گیت‌هاب نمی‌رود.

برای دیدن رمز این دستور را بزنید. رمز، متن ۳۲ حرفی‌ای است که در خروجی جلوی `ANDROID_KEYSTORE_PASSWORD` آمده:

</div>

```bash
cat android-signing/secrets.txt
```

<div dir="rtl">

### ۵-ب) گذاشتن چهار مقدار در گیت‌هاب (Secrets)

۱. در صفحه‌ی مخزن تب **Settings** را بزنید.

۲. در منوی سمت چپ روی **Secrets and variables** بزنید و بعد **Actions** را انتخاب کنید.

۳. دکمه‌ی سبز **New repository secret** را بزنید. در کادر **Name** نام را دقیقاً همان‌طور که در جدول زیر آمده (با حروف بزرگ) بنویسید، در کادر **Secret** مقدارش را بچسبانید و **Add secret** را بزنید.

۴. این کار را برای هر چهار مورد تکرار کنید:

| نام (Name) | مقدار (Secret) |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | کل متن داخل فایل `ANDROID_KEYSTORE_BASE64.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز ۳۲ حرفی از `secrets.txt` (فقط خود رمز، بدون علامت مساوی و فاصله) |
| `ANDROID_KEY_ALIAS` | کلمه‌ی `release` |
| `ANDROID_KEY_PASSWORD` | همان رمز ۳۲ حرفی |

متن فایل `ANDROID_KEYSTORE_BASE64.txt` یک خط خیلی بلند است و باید کامل کپی شود. ساده‌ترین راه، این دستور در ترمینال است که کل آن را کپی می‌کند؛ بعد در کادر **Secret** با Ctrl+V (در مک Command+V) بچسبانید:

</div>

```bash
# Windows (Git Bash)
clip < android-signing/ANDROID_KEYSTORE_BASE64.txt
# macOS
pbcopy < android-signing/ANDROID_KEYSTORE_BASE64.txt
```

<div dir="rtl">

در لینوکس فایل را با یک ویرایشگر متن باز کنید، همه را انتخاب کنید (Ctrl+A) و کپی کنید.

در آخر باید در همان صفحه، زیر **Repository secrets**، هر چهار نام را ببینید. مقدارها بعد از ذخیره دیگر نمایش داده نمی‌شوند؛ عادی است.

### ۵-ج) ساخت دوباره، این بار با فایل‌های اندروید

۱. تب **Actions** را بزنید و در فهرست سمت چپ **Build** را انتخاب کنید.

۲. سمت راست، دکمه‌ی **Run workflow** را بزنید. یک پنجره‌ی کوچک باز می‌شود:

- گزینه‌ی **Use workflow from** روی **Branch: main** باشد.
- تیک **Build the macOS installers too** همان‌طور زده بماند.
- تیک گزینه‌ی **Publish this version's release, also when it exists already (its files are replaced)** را بزنید.

۳. دکمه‌ی سبز **Run workflow** پایین همان پنجره را بزنید.

بعد از تمام شدن (حدود ۲۰ تا ۳۰ دقیقه)، سه فایل APK به نسخه‌ی v1.0.0 اضافه شده‌اند و لینک‌های اندروید صفحه‌ی دانلود هم کار می‌کنند. از این به بعد هر نسخه‌ی جدید خودش APK‌ها را دارد و این کار دیگر لازم نیست.

### ۵-د) نگهداری کلید (خیلی مهم)

- از کل پوشه‌ی `android-signing` دست‌کم دو نسخه‌ی پشتیبان در دو جای امن نگه دارید، مثلاً یک فلش و یک فضای ابری رمزدار.
- **اگر کلید گم شود:** دیگر نمی‌توانید آپدیتی بسازید که روی اپ نصب‌شده‌ی مشتری‌ها نصب شود؛ همه باید اپ را پاک و دوباره نصب کنند.
- **اگر کلید لو برود:** هر کسی می‌تواند نسخه‌ی جعلی‌ای بسازد که اندروید آن را آپدیت اپ شما حساب می‌کند. آن را برای کسی نفرستید و هیچ‌وقت در گیت‌هاب یا گروه و کانال نگذارید.

## گام ۶: پنل و ورود مشتری‌ها

### پنل

داخل اپ آدرس هیچ سروری نیست. مشتری لینک اشتراکش را وارد می‌کند و اپ همه چیز را (سرورها، پروتکل‌ها، حجم و تاریخ، اطلاعیه‌ها، پشتیبانی) از همان لینک می‌گیرد. پس عوض کردن سرور یا پنل، نسخه‌ی جدید اپ لازم ندارد.

اپ با پنل **Manifold** کار می‌کند، یا هر پنلی که همین API را داشته باشد. لینک اشتراک پنل‌هایی مثل 3x-ui یا Marzban به تنهایی کافی نیست، چون این آدرس‌ها را جواب نمی‌دهند. پنل باید روی لینک اشتراک، آدرس‌های جدول زیر را داشته باشد (در جدول، `sub link` همان لینک اشتراک است):

</div>

| Request | Purpose |
| --- | --- |
| `GET <sub link>?format=info` | the subscription's summary (JSON); the app signs in as the first name under `emails` |
| `POST <sub link>/app/v1/login` | session token for that account and this device |
| `GET <sub link>/app/v1/profile` | account, locations, every configuration, notices |
| `POST <sub link>/app/v1/logout`, `/disconnected`, `/report` | sign out, a device left a connection, a support report |

<div dir="rtl">

### ورود مشتری

- مشتری فقط لینک اشتراکش را در اپ می‌چسباند و **ورود** را می‌زند. نام کاربری لازم نیست.

</div>

```

```

## گام ۷: انتشار نسخه‌ی جدید

۱. تغییراتتان را در کد بدهید.

۲. فایل `package.json` را با یک ویرایشگر متن (مثل Notepad) باز کنید. در خطی که کلمه‌ی `version` دارد، عدد `1.0.0` را بالا ببرید، مثلاً به `1.0.1`، و فایل را ذخیره کنید.

- شماره‌ی نسخه همیشه باید از قبلی بیشتر باشد؛ اندروید نسخه‌ی پایین‌تر را روی بالاتر نصب نمی‌کند.
- هر کدام از سه عدد زیر ۱۰۰ بماند (مثل `1.0.1` یا `1.2.0` یا `2.0.0`)، چون شماره‌ی نسخه‌ی اندروید از همین سه عدد ساخته می‌شود.

۳. محتوای فایل `RELEASE_NOTES.md` را با تغییرات این نسخه عوض کنید. کل این فایل روی صفحه‌ی آن نسخه در Releases نمایش داده می‌شود.

۴. در ترمینال داخل پوشه‌ی `digi-cyber` (گام ۳-الف) این سه دستور را بزنید:

</div>

```bash
git add -A
git commit -m "Digi Cyber 1.0.1"
git push
```

<div dir="rtl">

۵. تب **Actions** را ببینید. وقتی تمام شد، نسخه‌ی v1.0.1 با همه‌ی فایل‌ها (اندروید هم) منتشر شده و همه‌ی لینک‌های دانلود خودکار به آن اشاره می‌کنند.

هر push که شماره‌ی نسخه را عوض نکند فقط ساخته و تست می‌شود و چیزی منتشر نمی‌کند. برای ساختن دوباره و جایگزین کردن فایل‌های همان نسخه‌ی فعلی، دکمه‌ی **Run workflow** را با تیک **Publish** بزنید (مثل گام ۵-ج).

| مشکل | راه حل |

| موقع commit پیام `Please tell me who you are` آمد | گام ۳-ب را انجام دهید و دستور `git commit` را دوباره بزنید. |

## گام ۱۰: کارهای اختیاری

- **امضای کد (Code signing):** بدون آن، ویندوز بار اول هشدار SmartScreen و مک هشدار Gatekeeper می‌دهد؛ راه عبور از هر دو در صفحه‌ی دانلود برای مشتری توضیح داده شده. برای حذف این هشدارها، برای ویندوز یک گواهی Code Signing و برای مک عضویت Apple Developer Program لازم است.
- **مجوز (License):** اگر می‌خواهید شرایط استفاده از سورس را مشخص کنید، یک فایل `LICENSE` اضافه کنید. مجوز اجزای متن‌باز داخل اپ در فایل `hub/THIRD-PARTY.md` است.
- **آدرس سایت:** در فایل `package.json` مقدار `homepage` فعلاً یک آدرس ساختگی (`digicyber.invalid`) است و فقط در اطلاعات بسته‌های لینوکس دیده می‌شود. اگر سایت یا کانال دارید، آدرسش را بگذارید.
- **ساخت روی کامپیوتر خودتان (برای برنامه‌نویس):** به Node.js نسخه‌ی ۲۲ نیاز دارد و دستورهایش پایین آمده است. ساخت اندروید به Android SDK و Go و gomobile هم نیاز دارد و ساده‌ترین راه، سپردنش به Actions است. جزئیات در فایل‌های `docs/development.md` و `android/README.md` است.

</div>

```bash
npm ci
npm test               # unit tests
npm run typecheck
npm run fetch-binaries # the engines (Xray, sing-box, WireGuard, ...) for this system
npm start              # builds and opens the app
```
